## 1. 반려 신청 재등록

### 현재 상태와 인터페이스

- `app/mileage/[status].tsx`는 반려일 때 기존 `MileagePhotoForm`에 보호 사진을 전달하고 `requirement="atLeastOne"`, `submitLabel="재등록"`을 사용한다. 제출 콜백만 `showMileageReRegistrationServerPendingAlert`다.
- 앱 `prepareMileageSubmission()`과 서버 `PhotoProcessorService.processPair()`는 두 사진 전용이다. 기존 폼은 유지하고 실제로 새로 선택한 파일만 준비·전송하는 경로를 추가해야 한다.
- `MileageUploadInterceptor`의 최대 두 파일 제한을 재사용한다. 서버 신규 신청은 두 장을 계속 요구하고 재등록은 한 장 또는 두 장을 받는다.
- `mileage_upload_attempts.storage_keys`의 기존 제약은 4개 키다. 한 장의 원본·정규화본은 2개 키이므로 실패 정리와 필요한 신규 마이그레이션을 함께 다뤄야 한다. 과거 `006-mileage-uploads.sql`을 수정해서 기존 DB 업그레이드를 생략하지 않는다.
- 지금 소스의 `MileageRepository.commit()`은 원신청 `idempotencyKey/requestHash`를 저장하고 사진별 ID·저장 키로 OCR `sourceVersion`을 계산한다. 이 경계를 실행 시 다시 읽는다.
- **제안 계약:** `POST /api/v1/mileage/applications/:id/resubmit`, multipart `idempotencyKey: UUID v4`, `submissionVersion: opaque string`, `receipt?`, `meter?`; 성공 `200`과 같은 신청 ID의 최신 상세. `submissionVersion`은 상세 API에 추가할 사진 제출 버전이며 원본 저장 경로를 노출하지 않는다. 기존 OCR 사진 버전 계산을 재사용할 수 있는지 확인한다.
- `submissionVersion`은 두 기기에서 오래된 반려 화면을 열어 둔 경우를 구분한다. 같은 재전송 키의 완료 여부를 먼저 확인한 뒤 새 변경의 현재 상태·버전을 검사한다.
- 제품 확인 지점은 두 개다. `submittedAt`을 최초 신청일로 유지할지 재등록 시각으로 바꿀지, 동일 파일을 재선택한 경우를 사진 변경으로 볼지다. 최소 제안은 최초 신청일 유지·선택한 파일만 교체다. 바이트 동일 파일 거부가 필요하면 비교 대상을 정하고 정확한 해시만 사용하며 시각 유사도 판정은 추가하지 않는다.

- 앱 `app/mileage/index.tsx`는 `<MileageBalanceCard />`에 값을 전달하지 않아 `-`를 표시한다. 데이터 연결은 기존 `AuthProvider.request`와 JSON 요청 함수로 충분하다.
- JSON 요청 함수에는 외부 AbortSignal 인자가 없다. 새 전송 계층을 만들지 말고 화면/사용자 수명 표식으로 늦은 결과를 무시한다. 필요 없는 인증 공통 함수 변경을 피한다.
- `다음달 10일 제휴사를 통해 정산돼요`는 고정 지급일이 없다는 최신 지시와 맞지 않는다. 제거 또는 대체 문구/영역 처리는 와이어프레임에서 확정한다. ‘곧 지급’, ‘자동 송금’ 같은 문구를 임의로 넣지 않는다.

제안 함수의 최소 형태는 기존 `utils/mileageApi.ts`의 `record`·`invalidResponse`를 재사용한다.

```ts
// 기존 import에 request as requestJson을 추가하는 방식으로 연결한다.
export async function getMileageSummary(session: SessionOptions) {
  const data = record(await requestJson('/mileage/summary', {
    ...session,
    expectedStatus: 200,
  }));
  const value = data.accumulatedMileage;
  if (typeof value !== 'number' || !Number.isSafeInteger(value) || value < 0) {
    return invalidResponse();
  }
  return { accumulatedMileage: value };
}
```

각 저장소에서 변경 전후 `git diff --check`를 확인한다. 실제 파일 이름과 scripts가 달라졌으면 최신 구성을 사용한다. 코드 모양을 문자열로 복제하는 검사보다 입력·응답·상태가 실제로 달라지는 검사를 선택한다. 검사하지 않은 플랫폼·실환경을 완료라고 보고하지 않는다.
