# 어드민 전체 페이지 QA

기준일: 2026-09-24. 관리자 웹의 실제 경로·현재 연결된 API·승인된 정책을 기준으로 작성한 수동 QA다. 모두 미실행으로 시작하며 직접 통과한 항목만 체크한다. 실패·보류는 체크하지 않고 별도 이슈로 기록한다. 정산·대시보드는 원본에 반영했고 임시 DB 검증과 사용자 DB 적용·은행 검증을 구분한다.

## 실행 환경과 기록 방법

| 항목 | 준비·확인 방법 |
|---|---|
| QA 페이지 | 앱 폴더에서 pnpm qa 실행 → http://127.0.0.1:4001/qa/admin. 유저 QA는 /qa/user다. 체크 결과는 서로 분리된다. |
| 관리자 웹 | [관리자 로그인](http://localhost:5173/login). 어드민 폴더에서 pnpm dev. URL 경로에는 #이 포함되지 않는다. |
| 서버 | http://localhost:8080/api/v1. 어드민의 /api/v1 요청은 기존 Vite 프록시를 사용한다. 서버와 웹 Origin 설정을 맞춘다. |
| 관리자 계정 | 사용자가 준비한 로컬 관리자 계정. ID·비밀번호·쿠키·토큰 값을 QA 문서/캡처에 남기지 않는다. |
| 사용자 계정 | [유저 로그인](http://localhost:4000/login). 서로 다른 물류사 소속의 본인 테스트 기사 2명, 탈퇴/비활성화용 계정은 별도로 준비한다. |
| 물류사 데이터 | 조회용 기존 테스트 물류사와 이번에 등록할 QA 전용 물류사. 고유한 사업자·법인 번호, 가상 담당자/계좌로 테스트하고 이름에 QA 표식을 붙인다. 실제 이체는 실행하지 않는다. |
| 주유소 데이터 | 조회용, 기기 여러 개, 좌표 없는 주유소와 실제 삭제해도 되는 별도 QA 주유소. 단일 기기는 등록 화면으로 준비하고 복수 기기·좌표 없는 데이터는 담당자가 격리 환경에서 사전 준비한다. |
| 날짜 데이터 | 기간 안/밖, 시작일 00:00, 종료일 늦은 시각, 다음 날 00:00 부근에 등록된 테스트 기사/주유소가 있으면 경계 검증에 사용한다. 없으면 해당 부분을 보류한다. |
| 브라우저 A/B | 서로 독립된 관리자 세션을 사용할 브라우저/시크릿 창. 탭 두 개는 쿠키를 공유한다. 동시 수정·삭제 대상은 QA 데이터만 쓴다. |
| 현재 상태 | 사유 없는 반려 API·화면 조작, 사용자 누적 잔액·재등록을 연결했다. 승인 버튼의 요청은 연결됐으나 서버 approve API는 미구현이다. 주유소 운영 상태는 UI 승인 대기다. 정산·대시보드는 임시 DB 검증과 실제 은행 송금을 구분한다. |

- 기본 순서: 로그인 → 전체 메뉴 조회 → 물류사·인프라 등록·수정 → 기사/인프라 조회·검색 → 미연동 페이지 UI → 마지막에 별도 테스트 데이터의 비활성화·탈퇴·삭제.
- 어드민은 데스크톱만 확인한다. 2026-09-22에 의미가 바뀐 주유소 사례는 새 ID를 부여해 이전 완료 체크를 승계하지 않는다. 기존 브라우저 체크는 지우지 않는다.
- 오프라인 전환, 요청 차단, 서버 중지 등 인위적인 연결 장애 테스트는 제외했다.
- ‘현재’는 바로 확인할 수 있는 항목, ‘연동 후’는 API/데이터/정책 준비 전까지 보류할 항목이다. ‘정책 비교’는 현행 구현이 기준과 다르면 실패로 남긴다.
- 조회는 화면 표시뿐 아니라 재진입으로 확인한다. 저장·비활성화·탈퇴·삭제는 실제 응답과 대상 식별자를 확인하고, 정상 응답 전에 목록에서 없어지는 것으로 통과하지 않는다.
- 최초 실패와 수정 후 재검증은 구분한다. 사례 ID / 브라우저 / 시각 / 테스트 대상 ID / 재현 순서 / 예상·실제 결과를 기록한다.
- 쿠키·세션 토큰·비밀번호·SMS 코드·재설정 토큰은 복사하지 않는다. 다른 사람의 개인정보가 들어간 데이터로 탈퇴/삭제를 재현하지 않는다.
- 2026-09-24 사용자 요청으로 사진 확대 구현 후 유저·어드민 전반 QA를 함께 실행한다. 5개 범위와 실행 제약은 docs/user-auth-qa.md의 ‘2026-09-24 전반 QA 범위’를 따른다. 현재는 목록 보완이며 신규 실행 결과가 아니다.
- 이번에 기대 동작이 바뀐 사례는 새 ID로 교체한다. 이전 브라우저 완료 체크와 과거 개발 검증 기록을 새 계약의 통과로 승계하지 않는다.

## 2. 대시보드 — /dashboard

2026-09-23 원본 정산·통계 연동 기준. 사용자 승인으로 공용 DB·모듈·의존성까지 반영했다. 아래 사례는 전용 테스트 환경에서 실행한다. AD-01~10의 샘플 검증 체크를 승계하지 않는다. 모든 날짜 경계는 한국 시간이다.

## 알려진 미완료·불일치

- 대시보드·정산과 사용자 앱 누적 잔액 카드는 연결됐다. 이번 전반 교차 QA는 아직 미실행이다. 사용자 DB 적용·배포와 은행의 실제 파일 접수·송금은 포함하지 않는다.
- 영수 조회·사진 모달·승인/반려 화면 조작과 사유 없는 반려 API는 연결됐다. 서버 approve API는 미구현이며 금액 불일치·수동 보정 정책이 남아 있다. 승인·정산 API 간 실제 경합은 구현 후 검증한다.
- 인프라 등록·수정은 연결됐다. 소재지·구분은 제거하고 주소 하나만 사용한다. 복수 기기 개별 편집과 운영 상태 변경은 보류한다. 실제 DB v7 업그레이드·배포는 아직 별도 확인 대상이며 자동 테스트 통과를 수동 QA 체크로 옮기지 않는다.
- 탈퇴는 이력 보존과 인증 수단 폐기, 물류사 비활성화는 기록 보존과 기사 세션 차단, 주유소 삭제는 기기 포함 실제 삭제다. 세 동작을 같은 삭제 정책으로 취급하지 않는다.
- 새로운 승인/정산 정책·은행 파일 규격·관리자 생성/로그아웃 UI를 이 문서에서 임의 확정하지 않는다.

## 최종 배포 전 QA 제거

QA는 별도 로컬 Node 서버이며 제품 앱/어드민 라우트를 추가하지 않는다. 최종 배포 작업에서 아래만 제거한다.

- scripts/qa.mjs, tests/qa.test.mjs, docs/user-auth-qa.md, docs/admin-qa.md.
- 앱 package.json의 qa 스크립트 한 항목. 제품 앱·어드민 파일이나 기존 테스트는 함께 지우지 않는다.
- QA 실행 서버를 종료하고 배포 산출물에 /qa/user·/qa/admin이 포함되지 않는지 확인한다.
- 브라우저 체크를 삭제할 때는 필요 결과를 먼저 보관하고 hpluseco:developer-qa:v2:user: 및 admin: 접두사에 해당하는 QA 키만 정리한다.

## 2026-09-23 정산·대시보드 개발 검증 기록

- 검증 환경: 원본을 보존한 `/private/tmp/hpluseco-settlement-work` 구현본, Nest 실제 HTTP 서버와 SQLite 메모리 DB, 별도 어드민 5196/API 8196. 사용자·운영 DB와 은행 시스템은 사용하지 않았다. 승인 API는 미구현이므로 확정 상태의 가상 신청을 DB 테스트 준비로 구성했다.
- 원본 반영 후 재검증: 사용자 승인 뒤 원본 서버·어드민에 23개 파일을 반영했다. 원본 기준 E2E 148개·서버 단위 47개·어드민 72개·QA 페이지 4개 통과, 서버/어드민 타입·린트·빌드 통과. 원본 소스와 메모리 DB로 다시 실행해 로그인, 9,000/9,000 조회, 8월 다운로드 뒤 대기 유지, 변조 파일 거부, 정상 파일 완료, 동일 파일 재업로드와 카드 0/0·건수 4/2 유지를 재확인했다. 사용자 수동 체크는 변경하지 않았다.
- 자동 검증: 정산 E2E, 최신 심사·인증·기사 마일리지 회귀, XLS/XLSX 유효/변조/중복/부분 제출/동시 처리, 사용자 전체 합계·목록 제외, 마이그레이션 데이터 보존·실패 롤백, 화면 상태·필터 응답 경합을 실행했다. 최종 개수와 결과는 개발 기록에 남긴다.
- 실제 브라우저 확인: 관리자 로그인 → 카드 9,000/9,000 및 일치 4·미일치 2 → 차트 소속 선택 → 8월 정산 3,000/6,000 조회 → 다운로드 요청 뒤 이체대기 유지 → 일부 금액 변조 파일 전체 거부 → 정상 파일 두 행 이체완료 → 동일 파일 재선택 → 대시보드 미정산 0/0, 건수 4/2 유지 → 빈 기간 0건과 빈 내역 표시.
