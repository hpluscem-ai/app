# 유저 전체 페이지 QA

기준일: 2026-09-24. 실제 앱 코드와 현재 승인 정책을 기준으로 작성한 수동 QA다. 모든 사례는 미실행으로 시작하며 실제로 통과한 항목만 체크한다. 실패·보류는 체크하지 않고 사례 ID와 재현 내용을 따로 기록한다.

회원가입 → 로그인 → 로그아웃 → 이메일 찾기 → 비밀번호 찾기 → 비밀번호 재설정 → 정보 수정 → 회원탈퇴 순서를 유지한다. 지도·마일리지는 정보 수정 뒤, 실제 탈퇴를 실행하기 전에 확인하거나 별도의 테스트 계정으로 확인한다.

## 실행 환경과 기록 방법

| 항목 | 준비·확인 방법 |
|---|---|
| QA 페이지 | 앱 폴더에서 pnpm qa 실행 → http://127.0.0.1:4001/qa/user. 어드민 체크리스트는 /qa/admin에서 별도로 기록한다. |
| 사용자 웹 / API | [사용자 로그인](http://localhost:4000/login), API http://localhost:8080/api/v1. 앱 웹은 pnpm web, API는 서버 폴더의 pnpm start:dev로 실행한다. 기존 실행이 있으면 중복 실행하지 않는다. |
| 어드민 | [어드민 로그인](http://localhost:5173/login). 같은 격리 QA 데이터로 회원·마일리지·정산·주유소를 교차 확인한다. |
| 테스트 물류사 | 앞선 준비에서 개발 DB에 등록한 활성 상태의 ‘테스트 물류사’. 시작 전에 실제 회원가입 소속 목록에 보이는지 확인한다. 비활성화는 별도로 만든 QA 물류사에서 마지막에 실행한다. |
| 계정 E / 번호 A | E는 수신 가능한 테스트 이메일 hpluscem@gmail.com, A는 담당자가 실제 SMS를 받을 수 있는 휴대폰이다. 기존 가입 여부를 확인하고 신규 가입 가능한 조합으로 준비한다. |
| 보조 계정·번호 B | 중복·미가입 조회·연락처 변경용 별도 계정/번호. 본인이 관리하는 번호만 사용한다. 없으면 해당 사례를 보류한다. |
| 비밀번호 P0 / P1 | 가입·재설정용으로 서로 다르게 정한다. 각각 영문·숫자·특수문자를 포함한 8자 이상. 실제 값은 QA에 쓰지 않는다. |
| 브라우저 A / B | A는 주 테스트, B는 다른 브라우저 또는 별도 시크릿 세션. 일반 탭 두 개는 쿠키를 공유하므로 다중 세션 확인용으로 사용하지 않는다. |
| 메일 | 서버 Git 제외 환경 파일에 Resend 테스트 발신과 http://localhost:4000/reset-password가 설정되어 있다. 현재 실행 서버의 반영 여부와 실제 수신을 다시 확인한다. 과거 임시 DB에서 받은 링크는 사용하지 않는다. |
| 모바일·네이티브 | PC 웹과 별도로 결과를 기록한다. localhost 메일 링크는 서버를 실행한 PC에서 연다. 실기기 연결 주소·앱 링크 설정이 없으면 링크 실행 항목을 보류한다. |
| 사진 | 식별 가능한 영수증/계기판 테스트 사진 2개, 허용 형식별 파일, 50 MiB 이하/초과 경계 파일을 준비한다. 실사용자 개인정보가 있는 사진은 쓰지 않는다. |

- 정상 동작은 입력 → 실제 제출 → 응답 확인 → 재진입/새로고침으로 저장 결과까지 확인한다.
- 오프라인 전환, 요청 차단, 서버 중지 등 연결 장애를 인위적으로 만드는 테스트는 제외했다.
- ‘현재’는 지금 확인할 항목, ‘연동 후’는 필요한 API·데이터가 갖춰질 때까지 보류할 항목이다. 화면만 열리거나 샘플이 보이는 것으로 서버 연동에 합격 표시하지 않는다.
- ‘정책 비교’는 승인된 기대 동작과 현행 구현을 대조하는 항목이다. 알려진 불일치는 그대로 실패로 기록한다.
- 시간 만료·다중 계정·기기·데이터가 필요한 항목은 선행 조건이 없으면 보류한다. 임의 성공 응답·가짜 인증 증명·토큰을 만들지 않는다.
- 결과는 사례 ID / 웹·iOS·Android / 브라우저·기기 / 시각 / 입력 조건 / 재현 순서 / 예상·실제 결과로 기록한다. 비밀번호·문자 코드·링크 토큰·세션·API 키는 캡처와 기록에서 가린다.
- 항목을 개편했으므로 기존 계정 전용 QA의 체크는 새 체크리스트에 자동 승계하지 않는다. 새 체크는 유저·어드민별로 현재 브라우저에 저장된다.

## 2026-09-24 전반 QA 범위

사용자 요청으로 사진 확대 구현 후 유저·어드민 교차 QA를 진행한다. 아래 5개 범위를 나눠 실행하며 현재는 목록 보완 단계다. 이 사이드 대화에서는 하위 에이전트를 사용할 수 없어 실행자가 순차 검증한다. 에이전트 5명의 독립 검증으로 기록하지 않는다.

| 범위 | 확인 대상 |
|---|---|
| 1. 인증·권한 | 가입·로그인·복원·정보 수정·복구·탈퇴, 기사/관리자 세션 분리, 타인 데이터 접근, 화면 이탈·계정 변경 응답 경합 |
| 2. 신청·재등록·사진 | 신규 신청 → 관리자 반려 → 한 장/두 장 재등록 → 양쪽 사진 대조, 중복 요청·저장 실패·이전 OCR, 승인된 네이티브 확대 |
| 3. 관리자 심사 | 필수 반려 사유·역사적 사유 보존·최신 reviewVersion·동시 심사, 승인·반려 API 계약 |
| 4. 잔액·정산 | 전체 미정산 승인 잔액, 기간/페이지 독립, 0과 미조회 구분, 결과 파일 업로드·재업로드·양쪽 합계 대조 |
| 5. 주유소·지도·화면 회귀 | 등록·수정·삭제의 지도 반영, 주유소/기기 데이터 보존, 웹·iOS·Android별 기존 화면과 사진 선택/삭제 회귀 |

- 실행은 격리 DB·테스트 계정·생성 사진·외부 서비스 대역을 기본으로 한다. 실제 사용자 DB 적용, 실제 송금, 유료 OCR·문자·메일 호출은 포함하지 않는다. 외부 서비스·실기기 준비가 없는 항목은 미검증으로 남긴다.
- 승인·반려·재등록과 잔액 조회는 현재 계약으로 확인한다. 금액 불일치 판단은 관리자가 실제 증빙을 근거로 수행하며, 주유소 운영 상태 변경은 개발 범위에 포함하지 않는다. 네이티브 확대는 실기기에서 별도로 확인한다.
- 과거 실행 기록은 당시 결과로 보존한다. 이번 재검증은 별도 결과와 증거를 남기며 변경한 사례에는 새 ID를 사용해 예전 완료 체크가 승계되지 않게 한다.
- 2026-09-27 최신 실행 결과와 미수정 문제는 [통합 QA 결과](qa-results-2026-09-27.md)를 기준으로 한다. 이 표의 개별 `미실행` 상태는 당시 수동 체크 이력이므로 일괄 변경하지 않는다.

## SMS 공통 — 각 인증 화면에서 반복

회원가입, 이메일 찾기, 비밀번호 찾기, 마이페이지의 기존 번호 인증과 변경 번호 인증에서 각각 적용한다. 별도 확인 버튼 없이 숫자 6자리 입력 시 서버 검증을 요청한다. 재현 시 필요한 문자는 테스트 담당자가 직접 요청한다.

| 결과 | ID | 구분 | 실행 절차 | 예상 결과 |
|---|---|---|---|---|

### 개발 검증 기록 — 2026-09-22

- 격리된 메모리 DB와 실제 서버를 사용한 웹 확인: 쿠키 로그인, 네이버 지도 로딩, 좌표 제외, 클러스터·복수 기기·주소, 지도 밖 선택 유지, 관리자 수정·삭제 반영, 실제 네이버 목적지 이동, 390×844 표시와 세션 폐기를 확인했다. 브라우저 런타임 오류는 0건이었다.
- 지도 API 500의 기존 데이터 보존과 범위 변경 후 재시도는 별도 격리 환경에서 확인했다. 이 기록을 위해 운영 서버 장애를 만들거나 일반 수동 QA에 연결 장애 유발 절차를 추가하지 않는다.

- 이 개발 검증 기록은 사용자의 수동 체크 결과와 별개다. 현재 환경에서 직접 확인한 사례만 체크한다.

## 마일리지 서버 — /api/v1/mileage/applications

현재 검증 범위는 비공개 사진·신규 신청·본인 목록/상세·요약·반려 재등록이다. 필수 반려 사유를 포함한 관리자 심사와 실제 재등록 API를 연결해 확인한다. MA-14의 OCR·자동 승인 운영 검증은 별도 보류하며 정산은 어드민 QA와 같은 격리 데이터로 대조한다.

- 서버 Swagger 또는 API 클라이언트에서 실행한다. 실제 로컬 Supabase Storage 사례는 [2026-09-27 통합 QA](qa-results-2026-09-27.md)에서 격리 버킷과 허가된 테스트 사진으로 확인했다. 운영 hosted 버킷·S3 키가 없으면 보류하며 로컬 결과를 운영 통과로 처리하지 않는다.
- 기본 경로는 /api/v1/mileage/applications다. 접수는 multipart/form-data의 receipt·meter 각 한 장과 idempotencyKey(UUID v4)를 함께 보낸다. 재시도할 때 같은 키와 같은 원본 바이트를 유지한다.
- 서로 다른 기사 A/B와 관리자 세션을 준비한다. DB·세션·실패 조건을 직접 바꾸는 사례는 담당자가 별도 격리 DB에서만 실행하며 기존 사용자 DB를 변경하지 않는다.
- 자동 테스트 결과와 수동 QA 체크는 별개다. 아래 항목은 모두 미실행으로 시작하고 실제 Supabase Storage 사용 여부·환경·시각·결과를 기록한 뒤 통과한 항목만 체크한다.
- 자동 검증 기록(2026-09-22): 이번 마일리지 커밋 대상만 담은 임시 사본에서 단위 31개·통합 533개, lint·타입 검사·빌드 통과. 기존 미커밋 SMS 변경과 다른 세션의 주유소 변경은 이 검증 사본에서 제외했다. 외부 저장소는 테스트 대역을 사용했으며 실제 R2 업로드·열람은 미검증이다.

## 알려진 불일치와 보류 기준

- WD-02: 탈퇴 확인창은 데이터 삭제를 말하지만 승인된 정책은 계정 원문·영수·정산 이력 보존이다. 문구를 이번 QA 작업에서 바꾸지 않는다.
- MR-101: 과거 사유는 보존하며 새 반려는 1~150자의 필수 사유를 저장한다. 재등록은 같은 ID·최초 신청일을 유지하고 동일 파일 재선택을 허용한다. 최신 전반 실행 결과는 [통합 QA 결과](qa-results-2026-09-27.md)를 따르며 이 표의 개별 체크는 보존한다.
- 마일리지 목록·신청·상세·사진·누적 잔액·재등록·승인/반려 API를 연결했다. 실제 로컬 Supabase Storage 흐름은 최신 통합 QA에서 확인했고, 운영 hosted Storage·iOS/Android 실기기·OCR 운영 검증은 별도로 남는다.
- MB-103: 정산 지급일은 고정되지 않는다. 기존 카드의 매월 10일 문구는 유지 요청에 따라 남아 있어 정책과 다르며 이번 QA에서 문구를 임의 수정하지 않는다.
- 개인정보·약관은 초안이다. 운영 정보 확정과 공개 전 문서 검토는 화면 QA 합격으로 대체하지 않는다.
- 오랜 시간 만료·추가 번호·다른 회원 이력·실기기가 필요한 사례는 준비가 되지 않으면 보류한다.

## 최종 배포 전 QA 제거

이 QA는 앱/어드민 제품 라우트나 public 정적 파일이 아닌 별도 로컬 Node 서버다. 테스트 확인을 위해 켠 서버는 종료한다.

- 제거 대상: scripts/qa.mjs, tests/qa.test.mjs, docs/user-auth-qa.md, docs/admin-qa.md와 package.json의 qa 스크립트 한 항목.
- 사용자 앱·어드민의 제품 페이지, 기존 테스트, 설정 파일은 함께 삭제하지 않는다.
- QA 체크는 현재 브라우저의 hpluseco:developer-qa:v2:user: 및 admin: 접두사 아래에만 저장한다. 필요하면 해당 QA 결과를 보관한 뒤 해당 키만 제거한다.
- 최종 배포 산출물에 /qa/user와 /qa/admin이 없고 QA 서버가 실행되지 않는지 확인한다. 실제 삭제는 최종 배포 작업 때 수행한다.
